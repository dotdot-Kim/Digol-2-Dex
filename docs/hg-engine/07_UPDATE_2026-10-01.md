## 1. 결론과 조사 범위

**이번 업데이트는 설치 환경·필드 스크립트 빌드·기존 폼 처리·배틀 기능에 의미 있는 변경이 있어 가이드 갱신이 필요합니다.** 디골의 종족/기술/트레이너 데이터를 C 원본으로 생성한다는 기본 방향과 진화 9슬롯 구조는 유지됩니다.

두 커밋 사이에는 **230개 커밋(merge commit 41개 포함)**이 있습니다. 날짜로 단순 필터하지 않고 이전 기준에서 최신 기준까지의 Git ancestry를 비교했습니다. 마지막 커밋 하나는 폼 동행 세이브 로드 수정이지만, 비교 대상은 그 이전에 함께 들어온 모든 변경입니다.

GitHub compare 파일 목록은 300개까지만 반환돼 그래픽 이후 경로가 빠졌습니다. 따라서 양쪽 **recursive Git tree가 truncated=false임을 확인하고 blob SHA를 대조**했습니다. 경로 기준 변화는 1,138개(수정 141·추가 763·삭제 234)입니다. 이 수치는 rename을 추가/삭제로 계산하며, 그래픽 이동을 포함하므로 1,138개의 독립적인 기능 변경을 뜻하지 않습니다.

변경된 C/ASM/빌드 파일과 테스트를 검토했고, 대형 `Species.c` 및 `learnsets.json`은 전체 blob을 받아 엔트리 단위로 비교했습니다. PNG 픽셀 전수검사나 실제 게임 실행은 이 조사에 포함하지 않습니다.

## 3. 설치·ROM 빌드

### 3.1 ds-rom이 기본

[`Makefile`](https://github.com/BluRosie/hg-engine/blob/027977cca9c93d5c7346081af837ec33706303f8/Makefile)에 `DSROM := tools/dsrom`, `ROM_TOOL ?= $(DSROM)`이 추가됐습니다. 빌드 시 ds-rom 저장소의 고정 커밋 `3bfef542191764df2afa39254bbf18f68c621d22`를 checkout하고 Cargo로 CLI를 만듭니다.

새 [`scripts/dsrom_bridge.py`](https://github.com/BluRosie/hg-engine/blob/027977cca9c93d5c7346081af837ec33706303f8/scripts/dsrom_bridge.py)가 `base_dsrom/config.yaml`과 파일/overlay 구조를 기존 엔진이 기대하는 `base/arm9.bin`, `base/overlay/`, `base/root/` 구조로 연결합니다. 데이터 generator와 hooks를 모두 다른 체계로 갈아엎은 변경은 아닙니다.

공식 README와 CI에 Rust 설치가 추가됐고 Python 의존성에는 PyYAML이 추가됐습니다. `clean`은 `base_dsrom/`도 삭제하며, 여러 도구 빌드 규칙은 재빌드 전에 해당 도구의 `make clean`을 실행하도록 바뀌었습니다. C/ASM include 경로 인용과 Cargo target 경로 보완도 들어갔습니다. 이것을 모든 공백 경로의 완전한 지원 보장으로 해석하지 않습니다.

### 3.2 확인된 전환 누락

1. **Dockerfile:** 비교 전후 동일하며 Rust/Cargo 설치가 없습니다. 기존 Docker 명령만으로 새 기본 경로가 준비된다고 안내할 수 없습니다.
2. **dump.mk:** 기본 `ROM_TOOL` 값은 `tools/dsrom`인데 `dump_prepare`는 `ifeq ($(ROM_TOOL),dsrom)`으로 비교합니다. 기본 dump는 legacy shell 경로를 타고 그 shell은 `tools/ndstool`을 직접 실행합니다. 새 checkout에서 ndstool이 없으면 이 경로가 실패할 수 있습니다.
3. **기존 venv:** 생성 target이 이미 충족돼 있으면 PyYAML 추가가 자동 설치되지 않을 수 있습니다.

이는 실제 코드에서 확인한 불일치/누락이며 이 환경에서 재현 실행한 오류라고 주장하지 않습니다. [01장](./01_SETUP_BUILD_CONFIG.md)에 설치·우회 절차를 반영했습니다.

## 4. 필드 스크립트·이벤트·텍스트

[`narcs.mk`](https://github.com/BluRosie/hg-engine/blob/027977cca9c93d5c7346081af837ec33706303f8/narcs.mk)와 [`dump.mk`](https://github.com/BluRosie/hg-engine/blob/027977cca9c93d5c7346081af837ec33706303f8/dump.mk)가 핵심입니다.

| 이전 | 최신 |
|---|---|
| `armips/scr_seq/`의 common/trainer `.s` | `data/scr_seq/`의 GNU ASM `.s` |
| `armips/include/scriptmacros.s`, flags/vars/soundeffects `.s` | `asm/include/`의 대응 `.inc` |
| 해당 파일에 Armips 실행 | assembler-with-cpp → link → objcopy |
| 이벤트 소스 빌드 경로 없음 | JSON → jsonproc 템플릿 → ASM → NARC 멤버 |
| `data/text/*.txt` 중심 | 엔진 텍스트 + `data/text/custom/*.txt` + `keys.csv` |

- 엔진 관리 `scr_seq_00003_commonscript.s`, `scr_seq_00953_trainerscript.s`는 항상 빌드합니다.
- 일반 덤프 스크립트는 `BUILD_DUMPED_SCR_SEQ`, 이벤트 JSON은 `BUILD_DUMPED_EVENTDATA`로 선택합니다. 둘 다 기본 비활성입니다.
- 토글은 Makefile이 값 없는 `#define` 행을 검사하므로 `#define NAME 1` 형식으로 켜지지 않습니다.
- NARC 전체를 빈 소스로 교체하지 않고 입력 ROM에서 추출한 뒤 빌드된 멤버만 덮습니다. 엔진이 관리하지 않는 DSPRE 변경을 보존하려는 구조입니다.
- 커스텀 텍스트에는 별도 토글이 없습니다. 생성해 두면 빌드 대상이 되므로 “스크립트 토글 OFF면 텍스트도 적용 안 됨”은 틀립니다.
- `keys.csv`로 원래 메시지 암호화 key를 전달합니다. 파일이 없으면 기존 msgenc 기본 key로 fallback합니다.
- 일반 맵 덤프 전체가 기준 Git tree에 포함돼 있지는 않습니다. 실제로 추적되는 파일과 덤프 후 생성 파일을 구분해야 합니다.

새 dumper는 기본적으로 엔진 관리 파일 및 generator가 재생성하는 텍스트를 제외합니다. `--include-engine-managed`와 `--include-generated-text`로 그 보호를 해제할 수 있습니다. 디골에서 사용할 편집 흐름은 [04장 43절](./04_WORLD_TRAINERS_ITEMS.md)에 정리했습니다.

|---|---:|---:|---:|
| Slash 위력 | 70 | 80 | 70 |
| Meteor Assault 위력 | 150 | 170 | 150 |
| Wish PP | 10 | 5 | 10 |
| Strength Sap PP | 10 | 5 | 10 |

`CHAMPIONS_POWER_CHANGES`/`CHAMPIONS_PP_CHANGES` 조건부 변화입니다. 모든 빌드에 무조건 적용됐다고 설명하면 안 됩니다. 테스트의 `GEN_LATEST`와 일반 빌드 세대 차이도 유지됩니다.

## 9. 커스텀 ID 충돌표

| 종류 | 이전 기준 | 최신 기준 | 새 커스텀 시작 예시 |
|---|---:|---:|---:|
| 마지막 특성 | 318 | 319 | 320 |
| `NUM_ABILITIES` | 319 | 320 | 사용자 추가 시 갱신 |
| `MAX_BASE_MOVE_EFFECT_NUM` | 406 | 408 | 409 |
| `MAX_BASE_SUBSCRIPT_NUM` | 519 | 522 | 523 |
| C `BASE_ENGINE_BTL_SCR_CMDS_MAX` | 0x11D (285; 실제 테이블과 불일치) | 0x12A (298) | 299 |
| 실제 기존 마지막 command | 0x125 (293) | 0x12A (298) | 299 |

이 번호들은 영구 예약이 아닙니다. 이전 가이드의 `ABILITY_DIGITAL_OVERDRIVE 319` 예시는 새 Aura Guard와 충돌하므로 바꿨습니다. 효과는 `MAX_BASE_MOVE_EFFECT_NUM + 1`, subscript는 `MAX_BASE_SUBSCRIPT_NUM + 1` 같은 기준 상대 표현을 사용하고 C/ASM dispatch를 함께 확인합니다.

`MoveConditionsFlags.glaiveRush`는 `wideOpen`으로 이름이 변경됐으며 `mindBlownOrSteelBeam`, `HealingWishQueue`, `field_condition2`, `magicRoomCounter`도 추가됐습니다. 구조체 offset에 의존하는 커스텀 ASM의 재검토가 필요합니다.

## 11. 이번 구간에서 변경되지 않은 핵심

양쪽 blob SHA가 동일한 것을 확인했습니다.

- `include/species_data.h`, `include/move_data.h`, `include/trainer_data.h`, `include/item.h`
- `data/Evolutions.c`, `src/individual/GetMonEvolutionInternal.c`
- `data/Trainers.c`, `data/Encounters.c`, `data/itemdata/itemdata.c`
- `include/constants/moves.h`, `include/constants/item.h`
- `src/item.c`, `scripts/build_learnsets.py`
- `scripts/build_tests.py`, `scripts/run_tests.py`, `scripts/run_tests.sh`

따라서 C 데이터 정본/generator 구조, 진화 9슬롯, 종족값의 C 필드 순서와 직렬화 순서 구분은 그대로 유효합니다. 새 TM 목록 체계로 전환된 업데이트도 아닙니다. 기존 구버전 converter가 자동으로 최신과 호환된다는 뜻은 아니며 converter migration은 별도 과제입니다.

## 12. 검증과 남은 작업

이번 작업은 매뉴얼 갱신입니다. 엔진 업데이트 자체를 디골 코드에 merge하거나 converter·종족 JSON·ROM을 수정하지 않았습니다.

- 전체 Git tree 대조로 API 파일 목록 상한에 따른 누락 방지.
- 기존 매뉴얼 7개와 핵심 변경 파일 내용 대조.
- Species/learnsets의 전체 blob 및 의미 있는 엔트리 비교.
- 배틀 테스트 파일 62개 추가·8개 수정 확인. 초기 PP가 고정 40에서 `GetMoveMaxPP(move, 0)`로 바뀐 점 반영.
- 최신 커밋의 공식 [`build` CI 성공](https://github.com/BluRosie/hg-engine/actions/runs/36866492892/job/110402006207) 확인.
- 로컬 US 원본 ROM clean build, 전체 배틀 테스트 실행, 실기/에뮬레이터 플레이 검증은 하지 않음. CI 성공을 디골 커스텀 기능의 검증으로 대신하지 않음.

실제 엔진 업데이트를 적용할 때는 설치 환경 → ID 충돌 → 폼/메가 호출부 → 필드 편집 정본 → clean build → 관련 배틀 테스트 → 폼 동행 세이브 로드 순으로 확인합니다.

## 13. 기존 가이드 자체의 정정

`asm/include/species.inc`를 C header와 함께 수동 편집하라는 예전 설명은 잘못됐습니다. 그 파일은 이전 기준과 최신 기준 트리에 모두 없습니다. 현재 GNU ASM은 C preprocessor를 통해 `include/constants/species.h`를 포함합니다. 관련 안내를 전체 가이드에서 수정했습니다.

이 항목은 **이번 upstream에서 파일이 삭제됐다는 설명이 아니라 기존 문서 오류의 정정**입니다. 또한 황금몸의 “상수 존재”와 “실제 구현”을 명확히 나눴습니다.
