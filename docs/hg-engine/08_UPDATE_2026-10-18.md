## 1. 기술머신 표의 원본

최신 upstream의 `src/item.c`는 `data/MachineMoves.c`의 표를 사용하며 `scripts/update_machine_moves.py`의 `--machines` 기본값도 새 경로로 바뀌었습니다 (`5e6c589`). 다음 두 표의 역할은 다릅니다.

| 편집할 내용 | 최신 upstream | 현재 디골 `c75d6f7` |
|---|---|---|
| TM/HM/TR 번호에 배정된 기술 | `data/MachineMoves.c`의 `sMachineMoves[]` | `src/item.c`의 `static const u16 sMachineMoves[]` |
| 특정 종이 배우는 머신 기술 | `data/learnsets/learnsets.json`의 `MachineMoves` | 같은 엔진 학습기 경로 및 디골 설치 도구 확인 |

현재 디골에는 `data/MachineMoves.c`가 없습니다. 새 upstream 가이드의 경로를 현재 fork에 이미 존재하는 것으로 설명하면 잘못입니다. GUI 편집기·변환기·기술머신 갱신 도구도 실제 기준 버전의 원본 경로를 사용해야 합니다.

## 2. 배틀 API와 번호

| 대상 | 10월 1일 | 10월 18일 |
|---|---|---|
| 마지막 upstream 특성 | Aura Guard 319 | 동일 |
| 마지막 기술 효과 | Steel Beam 408 | 동일 |
| 마지막 서브스크립트 | Prevent Intimidate 522 | Receiver 523 |
| 마지막 확장 배틀 명령 | `0x12A` = 298 | `0x12C` = 300 |
| 498번 서브스크립트 상수 | `BATTLE_SUBSCRIPT_HANDLE_WIMP_OUT` | `BATTLE_SUBSCRIPT_HANDLE_WIMP_OUT_EMERGENCY_EXIT` |

새 명령은 `0x12B TryActivateReceiver`, `0x12C TryActivateEmergencyExit`입니다. C dispatch, ASM 매크로, 스크립트 호출부를 함께 맞춥니다. 커스텀 시작 예시는 각각 subscript 524, 명령 301이지만 **현재 디골의 빈 ID를 보장하지 않습니다.** 디골 자체 상수와 기존 스크립트를 먼저 확인합니다.

`BattleStruct.waza_no_last`는 `lastSuccessfulMove`로 이름이 바뀌었습니다. `recoilDamage`, `ejectPackActivated`, `MoveConditionsFlags.ejectPackFlag`·`firstTurnOut` 등도 추가됐습니다. 구조체 offset에 의존하는 커스텀 ASM은 이름 교체만으로 이식을 끝낼 수 없습니다.

`ADD_STATUS_*` 중복 정의는 제거됐고 `SIDE_EFFECT_TYPE_CONTACT_PROTECTED` (`0xA`)가 추가됐습니다. 사용 코드를 `SIDE_EFFECT_TYPE_*` 정의와 대조합니다.

Emergency Exit/Wimp Out은 반동·독/화상·나이트메어·저주·바인드 등 여러 피해 단계와 설치기 교체 처리를 함께 변경합니다. Fake Out은 교체를 반영하는 첫 턴 판정으로 바뀌었고 Eject Pack/Button, Knock Off, Incinerate, Unburden, Metal Burst, Protect 관련 수정도 있습니다. 관련 회귀 테스트가 추가됐다는 사실과 이 문서 작업에서 직접 테스트를 실행했다는 것은 다릅니다.

## 4. 현재 디골 프로젝트와 해결된 안정화 이력

사용자는 프리징과 BGM 문제가 해결됐음을 확인했습니다. 현재 저장소의 `digol/docs/CHANGELOG.md`에는 10월 20일 수정과 DeSmuME 검증이 기록되어 있습니다.

| 해결된 증상 | 저장소에 기록된 수정 |
|---|---|
| BGM 전체 무음 | 라디오 힙을 `0x10000`에서 원본 `0x2EE0`으로 복구. 원본 라디오 9곡으로 지방사운드 구성 |
| 연구소 스타팅 직전 멈춤 | 삽입 스크립트 4바이트 정렬 유지, bank 129 #34 누락 메시지 보완 |
| 세이브 로딩 직후 멈춤 | 비전머신 모듈의 `Bag_HasItem` 호출에 `long_call` 추가. 빌드 시 veneer 검사 도입 |

저장소 기록의 검증 범위는 타이틀 BGM, 새 게임→연구소→브이몬 수령→닉네임→저장→이어하기, 기존 `test.dsv` 이어하기·필드 이동, 지방사운드 순환/끄기/복원입니다. 이 문서 작업에서 해당 플레이를 재실행하지는 않았습니다.

현재 빌드 구조:

| 역할 | 현재 경로 |
|---|---|
| 옵션·소스 목록 | `digol/config.mk` |
| 빌드 규칙·4개 레시피 훅 | `digol/digol.mk` |
| 상주/전투/필드 코드 | `digol/src/`, `digol/src/battle/`, `digol/src/field/` |
| 헤더·한글화 | `digol/include/`, `digol/localization/`, `digol/scripts/` |
| 원본 사본·변환/설치 | `digol/source/`, `digol/tools/`, `data/digol/*.inc` |
| 구버전 이식·비전머신 | `digol/legacy/`, `digol/hm/` |
| 지방사운드 | `digol/regional_radio/music.json`, `digol/src/field/digol_regional_radio.c` |
| 빌드 검사 | `digol/scripts/check_build.py`의 `veneers` / `layout` |

지방사운드 설정과 C 표는 함께 수정합니다. 현재 라디오 원본 곡 9개는 지방끼리 중복되지 않으며, 힙·사운드 데이터를 확장하지 않습니다.

상주 오버레이 129 최적화는 전체 한글 음절표를 a/0/2/8 멤버 20으로 옮기고, 받침 표만 상주시킨 방식입니다. 경험치 공유 계산은 전투 오버레이 130으로 이동했습니다. 변경 기록의 129 잔여 2,281 B는 10월 20일 해당 빌드 수치입니다. 향후 추가 가능 용량은 현재 빌드의 `layout` 출력으로 판단합니다.

`species_integration.json`처럼 과거 단계의 `NOT VERIFIED` 표시가 남아 있는 메타데이터와 최신 안정화 기록의 검증 범위를 구별합니다. 이 표시는 현재 프로젝트 전체가 빌드/플레이 미검증이라는 근거가 되지 않습니다.

## 5. 빌드·덤프 갱신과 남은 버전 차이

upstream `975d0a3`는 `dump.mk`의 `ifeq ($(ROM_TOOL),dsrom)`을 `ifeq ($(ROM_TOOL),$(DSROM))`으로 수정했습니다. 현재 디골 `c75d6f7`의 덤프 파일은 아직 이전 비교를 사용합니다. 이 가이드에서 게임 소스를 병합하거나 해당 분기를 수정하지는 않았습니다.

최신 upstream은 일부만 엔진이 관리하는 NARC를 매번 재생성하여 `base/root`에 다른 도구가 적용한 수정이 오래된 산출물에 덮이지 않도록 했습니다. 투명 텍스트박스 폰트·프레임 설치 토글, `a028/8_2*` 정리 경로와 Spiky Shield 파티클 파일명도 수정됐습니다. 필드 덤프는 동적 맵 헤더 처리와 스크립트 include 경로 안내가 보완됐습니다.

Dockerfile에는 여전히 Rust/Cargo 설치가 없으므로 기존 가이드의 주의는 유지합니다. 디골의 최상위 mk 파일을 upstream 것으로 통째로 교체하면 `digol/` 훅·한글화·빌드 검사 연결을 잃을 수 있습니다. 파일별 diff로 통합합니다.
